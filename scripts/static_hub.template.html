III — Método

El mismo proceso para los seis productos, sin importar el lenguaje o la base de datos.

01Problema antes que stack

Cada producto parte de una molestia cotidiana concreta y de quién la sufre.

02Especificación escrita

Spec-Driven Development: el contrato y las reglas de dominio se escriben antes del código.

03Dominio aislado

Arquitectura limpia: la lógica de negocio no depende de frameworks ni de la base de datos.

04Pruebas antes del merge

GitFlow con dev como único origen; main solo recibe versiones con CI en verde.
